# 01 — Linux Commands for DevOps: Complete Command Handbook

> **Purpose:** A single reference for Linux commands, shortcuts, networking, troubleshooting, logs, processes, and daily DevOps work.
>
> **Environment:** Ubuntu Linux / Ubuntu EC2 on AWS.
>
> **How to learn:** Understand the command, copy it, run it, and observe the output. Replace example values such as `PID`, `PORT`, `SERVICE_NAME`, and `SERVER_IP` with actual values.

---

# 1. Understand the Linux terminal

Example terminal prompt:

```text
root@ip-172-31-2-84:/etc/apt/apt.conf.d#
```

Understand every part:

| Part | Meaning |
|---|---|
| `root` | Current user |
| `ip-172-31-2-84` | Server hostname |
| `/etc/apt/apt.conf.d` | Current working directory |
| `#` | Usually indicates a root shell |
| `$` | Usually indicates a normal user shell |

Your terminal prompt is not a command. Type commands after the prompt.

For example:

```bash
hostname -I
```

Output:

```text
172.31.2.84 172.17.0.1
```

This means your machine has multiple IP addresses assigned to its network interfaces.

- `172.31.2.84` is likely your EC2 instance's private IP address.
- `172.17.0.1` is commonly the Docker bridge gateway address when Docker networking is configured.

To inspect the interfaces:

```bash
ip -br addr
ip route
```

## 1.1 Basic command structure

```bash
command [options] [arguments]
```

Example:

```bash
ls -lah /var/log
```

- `ls` — list directory entries.
- `-l` — detailed listing.
- `-a` — include hidden entries.
- `-h` — human-readable file sizes.
- `/var/log` — directory to inspect.

**Remember:** Command = what to do, option = how to do it, argument = where or what to act on.

# 2. Short commands and command abbreviations

These are commonly used shortcuts that DevOps engineers should recognise.

| Short command | Full command or meaning | Purpose |
|---|---|---|
| `ip a` | `ip addr` | Show network interfaces and IP addresses |
| `ip r` | `ip route` | Show routing table |
| `ip l` | `ip link` | Show network interfaces and link state |
| `df -h` | Disk free, human-readable | Check filesystem space |
| `du -sh DIR` | Disk usage summary | Check directory size |
| `ps aux` | Process status options | List processes |
| `ss -tuln` | Socket statistics | List listening TCP/UDP sockets |
| `ll` | Often an alias for `ls -l` | Detailed directory listing |
| `la` | Often an alias for `ls -A` | Show hidden entries except `.` and `..` |
| `cls` | Common on Windows, not a standard Bash command | Use `clear` on Linux |
| `pwd` | Print working directory | Show current directory |
| `df -i` | Filesystem inode usage | Check inode availability |
| `free -h` | Memory report | Check RAM and swap |

Check aliases:

```bash
alias
type ll
type ip
```

## 2.1 `ifconfig` versus `ip a`

Both can display network interface information, but `ip` is the preferred modern Linux tool.

```bash
ip a
ip addr
ip -br addr
```

Older command:

```bash
ifconfig
```

If Ubuntu reports `ifconfig: command not found`, the utility may not be installed. It is provided by the `net-tools` package.

```bash
sudo apt-get update
sudo apt-get install net-tools
```

Use `ip a` for normal troubleshooting instead of installing older tools just for this purpose.

## 2.2 `nslookup` and `dig`

These commands inspect DNS lookups.

```bash
nslookup google.com
dig google.com
```

If `dig` is missing on Ubuntu:

```bash
sudo apt-get install dnsutils
```

Depending on the Ubuntu release, the package name may be different. Check availability with:

```bash
apt-cache policy dnsutils
```

## 2.3 Check whether a command exists

```bash
command -v docker
command -v git
command -v nslookup
```

If the command is installed and available in your `PATH`, the shell usually prints its path.

# 4. Linux symbols you must understand

These symbols are essential for shell scripting, log analysis, and troubleshooting.

## 4.1 Pipe `|`

Sends one command's standard output to another command's standard input.

```bash
ps aux | grep docker
```

Meaning:

1. `ps aux` lists processes.
2. `|` passes that output onward.
3. `grep docker` selects lines containing `docker`.

More examples:

```bash
ls -lah | less
journalctl -u docker | grep -i error
ip a | grep inet
```

A pipe sends standard output by default, not standard error.

## 4.2 Greater than `>`

Redirects output into a file, replacing existing contents.

```bash
echo "Hello DevOps" > notes.txt
```

**Warning:** If `notes.txt` already exists, its previous contents are replaced.

## 4.3 Double greater than `>>`

Appends output to the end of a file.

```bash
echo "Second line" >> notes.txt
```

## 4.4 Error redirection `2>`

Saves standard error in a file.

```bash
ls /not-found 2> errors.txt
```

Read the error:

```bash
cat errors.txt
```

## 4.5 `2>&1`

Redirects standard error to wherever standard output is currently going.

```bash
some-command > output.log 2>&1
```

This saves both standard output and standard error to `output.log`.

Redirection order matters. `> output.log 2>&1` is not equivalent in all situations to `2>&1 > output.log`.

## 4.6 Logical AND `&&`

Runs the second command only if the first succeeds.

```bash
mkdir practice && cd practice
```

## 4.7 Logical OR `||`

Runs the second command if the first command fails.

```bash
command -v docker || echo "Docker is not available in PATH"
```

## 4.8 Semicolon `;`

Runs commands sequentially regardless of whether the preceding command succeeds.

```bash
date; hostname; pwd
```

## 4.9 Dollar sign `$`

Used for variables and command substitution.

```bash
echo "$HOME"
echo "$USER"
```

Command substitution:

```bash
CURRENT_DIR=$(pwd)
echo "$CURRENT_DIR"
```

## 4.10 Wildcards `*` and `?`

```bash
ls *.log
ls file?.txt
```

- `*` matches zero or more characters in filename patterns.
- `?` matches one character in filename patterns.

## 4.11 Quotes

```bash
echo "Hello DevOps"
echo 'Hello DevOps'
```

Double quotes allow variable expansion:

```bash
NAME="Santhosh"
echo "Hello $NAME"
```

Single quotes treat the text literally:

```bash
echo 'Hello $NAME'
```

Output:

```text
Hello $NAME
```

## 4.12 Comments `#`

In a Bash script, text after `#` is a comment when it is not part of a quoted string or another special construct.

```bash
# Check the current hostname
hostname
```

## 4.13 Exit status `$?`

Shows the exit status of the most recently executed command.

```bash
ls /tmp
echo $?
```

Usually:

- `0` means success.
- Non-zero means some kind of failure.

Check it immediately after the command you want to inspect, because running another command changes `$?`.

# 6. Search, filter, and count commands

## 6.1 `grep`

Searches text.

```bash
grep "error" app.log
grep -i "error" app.log
grep -n "error" app.log
grep -in "failed" app.log
grep -r "TODO" .
grep -v "success" app.log
```

| Option | Meaning |
|---|---|
| `-i` | Ignore case |
| `-n` | Show line numbers |
| `-r` | Search recursively |
| `-v` | Show lines that do not match |
| `-w` | Match whole words |
| `-c` | Count matching lines |

## 6.2 Combine `grep` with other commands

```bash
ps aux | grep nginx
journalctl -u docker | grep -i error
ip a | grep inet
```

Note: `ps aux | grep nginx` may show the `grep` process itself. For process-specific searches, `pgrep -a nginx` can be more convenient.

## 6.3 `sort`, `uniq`, `wc`, `cut`, and `awk`

```bash
sort names.txt
sort names.txt | uniq
sort names.txt | uniq -c
wc -l app.log
cut -d: -f1 /etc/passwd
awk '{print $1}' notes.txt
```

| Command | Purpose |
|---|---|
| `sort` | Sort lines |
| `uniq` | Remove adjacent duplicate lines |
| `uniq -c` | Count adjacent identical lines |
| `wc -l` | Count lines |
| `cut` | Extract delimited fields |
| `awk` | Process columns and text patterns |

## 6.4 `xargs`

Builds command arguments from input.

```bash
printf '%s\n' one two three | xargs echo
```

Be cautious when combining `xargs` with commands that delete or modify files.

# 7. Networking commands — essential for DevOps

## 7.1 View IP addresses

```bash
ip a
ip addr
ip -br addr
hostname -I
```

Difference:

- `ip a` — shows detailed interface and address information.
- `ip -br addr` — shows a shorter, brief summary.
- `hostname -I` — prints assigned IP addresses in a space-separated list.

## 7.2 Inspect network interfaces

```bash
ip link
ip -br link
```

Look for interface state, such as `UP` or `DOWN`.

## 7.3 Check routing

```bash
ip route
ip r
```

Shows routes and the default gateway.

## 7.4 Test connectivity

```bash
ping -c 4 8.8.8.8
ping -c 4 google.com
```

- First command tests reachability to an IP address.
- Second command also requires the hostname to resolve through DNS.

Ping can be blocked by firewalls, so a failed ping does not always prove a server is down.

## 7.5 DNS troubleshooting

```bash
nslookup google.com
dig google.com
getent hosts google.com
```

| Command | Purpose |
|---|---|
| `nslookup` | Query DNS |
| `dig` | Detailed DNS query results |
| `getent hosts` | Test name resolution using the system's configured name service |

## 7.6 Check listening ports

```bash
ss -tuln
ss -tulnp
ss -lnt
```

| Option | Meaning |
|---|---|
| `-t` | TCP |
| `-u` | UDP |
| `-l` | Listening sockets |
| `-n` | Numeric addresses and ports |
| `-p` | Process details where permitted |

Example: Check whether a service is listening on port 80.

```bash
ss -lnt | grep ':80'
```

If nothing is returned, no matching TCP listening socket was found by that command.

## 7.7 Test a specific TCP port

```bash
nc -vz example.com 443
```

`nc` (netcat) can test TCP connectivity when installed. If unavailable, check the package before installing it.

For a local web server:

```bash
curl -I http://127.0.0.1:8080
```

Replace `8080` with the actual port.

## 7.8 HTTP and HTTPS checks

```bash
curl -I https://example.com
curl -sS -o /dev/null -w '%{http_code}\n' https://example.com
```

The second command prints the HTTP response status code, such as `200`, `301`, `403`, or `500`.

Remember:
- `200` — successful response.
- `301` or `302` — redirect.
- `403` — forbidden.
- `404` — resource not found.
- `500` — server-side error.

## 7.9 DNS and port troubleshooting sequence

If a website is not opening, try:

```bash
getent hosts example.com
curl -I https://example.com
ip route
```

For a service you administer, also check:

```bash
ss -tuln
systemctl status SERVICE_NAME
journalctl -u SERVICE_NAME -n 50
```

This checks name resolution, HTTP response, routing, listening sockets, service status, and service logs.

## 7.10 Check local addresses versus public addresses

```bash
hostname -I
ip -br addr
```

On AWS EC2, a private IP is used for internal networking. The public IPv4 address, if assigned, is a separate concept and may not appear as a local interface address inside the instance.

To find the public address, use the AWS console or an approved AWS metadata/service method. Do not assume the first address from `hostname -I` is public.

# 8. Processes and system performance

## 8.1 `ps`

```bash
ps
ps aux
ps -ef
```

Shows processes and information such as PID, user, CPU, and memory.

## 8.2 Search processes

```bash
pgrep -a docker
pgrep -a nginx
ps aux | grep '[d]ocker'
```

`pgrep -a` displays matching process IDs and command lines on supported systems.

## 8.3 `top`

```bash
top
```

Shows a live view of CPU usage, memory usage, system load, and running processes.

Useful keys:
- `q` — quit.
- `P` — sort by CPU in common procps versions.
- `M` — sort by memory in common procps versions.

## 8.4 `htop`

```bash
htop
```

Provides an interactive process monitor with a more visual display. It may need installation:

```bash
sudo apt-get install htop
```

## 8.5 Check CPU information

```bash
lscpu
nproc
uptime
```

- `lscpu` — CPU architecture and configuration.
- `nproc` — number of processing units available to the process.
- `uptime` — uptime and load averages.

## 8.6 Check memory

```bash
free -h
cat /proc/meminfo
```

## 8.7 Check disk usage

```bash
df -h
df -h /
df -i
du -sh /var/log
```

- `df -h` — filesystem space.
- `df -i` — inode availability.
- `du -sh` — directory usage summary.

A filesystem can run out of inodes even when some disk space remains.

## 8.8 Check processes consuming resources

```bash
ps aux --sort=-%cpu | head
ps aux --sort=-%mem | head
```

These commands show processes sorted by CPU usage or memory usage.

## 8.9 Stop a process

```bash
kill PID
```

Replace `PID` with the correct process ID.

The default signal requests graceful termination. Use `kill -9 PID` only as a last resort because it prevents the process from handling normal cleanup.

Never kill a process just because it uses high CPU; first understand what it is doing.

# 9. Services and system logs

## 9.1 `systemctl`

```bash
systemctl status docker
sudo systemctl start docker
sudo systemctl stop docker
sudo systemctl restart docker
sudo systemctl enable docker
sudo systemctl enable --now docker
```

- `status` — inspect the service.
- `start` — start it now.
- `stop` — stop it.
- `restart` — restart it.
- `enable` — configure automatic startup at boot.
- `enable --now` — enable and start it.

A service can fail to start because of configuration errors, missing packages, permissions, or unavailable resources.

## 9.2 `journalctl`

```bash
journalctl -u docker
journalctl -u docker -n 50
journalctl -u docker --since today
journalctl -u docker -f
```

Useful options:
- `-u` — select a service unit.
- `-n 50` — show the latest 50 entries.
- `--since today` — restrict by time.
- `-f` — follow new entries.

## 9.3 `dmesg`

```bash
dmesg -T | tail -n 50
```

Shows recent kernel messages, which may help diagnose device, memory, or driver issues.

## 9.4 Check whether a service exists

```bash
systemctl list-unit-files --type=service
systemctl status docker
```

If `docker.service could not be found`, Docker may not be installed as a system service, or the service may have a different name.

| Command | Purpose |
|---|---|

# 11. Users, permissions, and ownership

## 11.1 User information

```bash
whoami
id
groups
who
w
```

## 11.2 Permissions

```bash
ls -l notes.txt
chmod 644 notes.txt
chmod 755 script.sh
```

`644` usually means the owner can read and write, while group and others can read.

`755` usually means the owner can read, write, and execute, while group and others can read and execute.

## 11.3 Ownership

```bash
sudo chown username:groupname notes.txt
```

Replace the example names with a real user and group.

## 11.4 Check the current identity and privileges

```bash
whoami
id
sudo -l
```

Use `sudo` only when necessary. Avoid running ordinary development tasks as `root`.

# 12. SSH, SCP, and remote server access

## 12.1 Connect to a server

```bash
ssh username@SERVER_IP
```

For EC2 with a private key:

```bash
ssh -i /path/to/key.pem ubuntu@SERVER_IP
```

Use the correct username, key path, and server address.

## 12.2 Copy a file to a remote server

```bash
scp notes.txt username@SERVER_IP:/tmp/
```

## 12.3 Copy a file from a remote server

```bash
scp username@SERVER_IP:/tmp/notes.txt .
```

## 12.4 Check SSH service

On Ubuntu, the service is commonly named `ssh`:

```bash
systemctl status ssh
```

The SSH server package must be installed for the service to exist.

## 12.5 SSH troubleshooting

Check:

1. Is the server running?
2. Is the username correct?
3. Is the private key correct and protected?
4. Does the EC2 security group allow inbound TCP port 22 from your client IP?
5. Does the network route permit the connection?
6. Is the SSH service running?
7. Is the server using a different SSH port?

Useful client-side command:

```bash
ssh -v username@SERVER_IP
```

Verbose mode provides more details about the connection attempt. Do not share private keys or sensitive authentication information when sharing logs.

# 15. Common Linux errors and what they mean

| Error | Meaning | What to check |
|---|---|---|
| `command not found` | Command unavailable in PATH or not installed | `command -v COMMAND` |
| `Permission denied` | Insufficient permissions or access blocked | `ls -l`, `id`, file permissions |
| `No such file or directory` | Path or file is missing, or a referenced interpreter is unavailable | `pwd`, `ls -l PATH` |
| `Package has no installation candidate` | No installable candidate in enabled package sources | Package name, repositories, `apt-cache policy` |
| `Unit docker.service could not be found` | Systemd cannot find that service unit | Check installation and service name |
| `Address already in use` | Another process may occupy the port | `ss -ltnp` |
| `Connection refused` | Host is reachable but the connection was rejected, or no service is listening | Service status and listening port |
| `Connection timed out` | Connection did not complete in time | Firewall, security group, routing, host availability |
| `Could not resolve host` | Name resolution failed | `getent hosts`, `nslookup`, DNS configuration |
| `No space left on device` | Disk space or inodes may be exhausted | `df -h`, `df -i` |
| `Out of memory` | Memory pressure may have caused allocation failure or a process termination | `free -h`, `top`, kernel logs |
| `Broken pipe` | A process wrote to a pipe whose reader closed it | Review the pipeline and process behavior |

# 16. DevOps troubleshooting cookbook

Use these workflows as a starting point when something breaks.

## Problem A: Website is not opening

```bash
hostname
ip -br addr
ip route
getent hosts example.com
curl -I --max-time 10 https://example.com
```

For a service on your own server:

```bash
systemctl status SERVICE_NAME
ss -tuln
journalctl -u SERVICE_NAME -n 50
```

Also check AWS security groups, network ACLs, route tables, DNS records, and load balancer health checks when relevant.

## Problem B: Docker is not working

```bash
docker --version
command -v docker
systemctl status docker
journalctl -u docker -n 50
```

If the service is installed but stopped, inspect the logs before attempting a restart.

## Problem C: Server disk is full

```bash
df -h
df -i
du -xhd1 /var 2>/dev/null
```

The final command summarizes immediate subdirectories of `/var` on the same filesystem, where supported by the installed `du` version.

Do not delete logs or Docker data blindly. Identify what is consuming space and determine what is safe to remove.

## Problem D: Application is using too much CPU

```bash
uptime
top
ps aux --sort=-%cpu | head
```

Identify the process, then inspect its logs and configuration before stopping it.

## Problem E: Application is using too much memory

```bash
free -h
ps aux --sort=-%mem | head
journalctl -k -n 100
```

Check for memory pressure and possible out-of-memory events.

## Problem F: DNS is failing

```bash
getent hosts example.com
nslookup example.com
cat /etc/resolv.conf
```

A successful DNS lookup does not guarantee that the destination website or port is reachable.

## Problem G: A service failed to start

```bash
systemctl status SERVICE_NAME
journalctl -u SERVICE_NAME -n 100
systemctl cat SERVICE_NAME
```

Inspect the reported error, configuration, dependencies, permissions, and required ports before making changes.

## Problem H: A port is already occupied

```bash
ss -ltnp
```

Find the relevant port and process. Confirm what the process does before stopping it.

# 17. Daily DevOps server health-check commands

These commands are generally read-only and useful for routine inspection:

```bash
date
hostname
uptime
whoami
ip -br addr
ip route
df -h
df -i
free -h
ps aux --sort=-%cpu | head
ps aux --sort=-%mem | head
ss -tuln
```

For a specific service:

```bash
systemctl status SERVICE_NAME
journalctl -u SERVICE_NAME -n 50
```

For Docker, if installed:

```bash
docker ps
docker ps -a
docker images
docker stats --no-stream
```

These commands help you assess the server; they do not replace application-specific monitoring or alerting.

# 20. Important safety rules

1. Confirm the current directory with `pwd` before modifying files.
2. Check the exact target with `ls -l` before deleting or changing ownership.
3. Do not use `rm -rf` on paths you have not carefully verified.
4. Do not restart or stop production services without understanding the impact.
5. Use `sudo` only when required.
6. Never publish passwords, SSH private keys, AWS credentials, or tokens to GitHub.
7. Do not copy commands blindly from the internet.
8. Review `curl | sh` or `wget | sh` installation instructions carefully before using them.
9. Treat command output as evidence, not always as the full diagnosis.
10. Practise destructive operations only in a disposable test environment.
